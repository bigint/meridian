This page lists every command that comes with Meridian, and what it does. Run them from the root of a Meridian checkout, or inside the running container through [Kamal](/reference/glossary#kamal).

## Kamal aliases

Meridian's `config/deploy.yml` defines two aliases:

| Command | Runs |
| --- | --- |
| `kamal console` | `kamal app exec --interactive --reuse "bin/rails console"`, a Rails console in the running container |
| `kamal logs` | `kamal app logs -f`, which shows Meridian's log and keeps following it |

To run any task below in production, wrap it in `kamal app exec`:

```bash
kamal app exec --reuse "bin/rails meridian:setup_code"
```

## Rake tasks

<ResponseField name="bin/rails meridian:setup_code" type="task">
  Prints the setup code that `/first_run` asks for before it creates your account. Meridian derives the code from `SECRET_KEY_BASE`, so it stores nothing. Meridian also logs it as `Meridian setup code: …` each time someone opens `/first_run`.
</ResponseField>

<ResponseField name="bin/rails db:prepare" type="task">
  Creates every database, or brings it up to date with the newest migrations. The image runs it before the server starts. See [Upgrading](/operate/upgrading).
</ResponseField>

## Scripts in bin

<ResponseField name="bin/setup" type="script">
  Installs gems, prepares the database, clears logs and temporary files, then starts the development server. You can run it again safely.

  - `--skip-server` stops before the server.
  - `--reset` also resets the database.
</ResponseField>

<ResponseField name="bin/dev" type="script">
  Starts the development server, `bin/rails server`, on port 3000. It passes any arguments on to `bin/rails server`.
</ResponseField>

<ResponseField name="bin/ci" type="script">
  Runs every check a change must pass, as `config/ci.rb` lists them. They are setup, RuboCop, `bundler-audit`, the importmap audit, Brakeman, and the agent's `go vet`, `staticcheck` and `go test -race`.
</ResponseField>

<ResponseField name="bin/jobs" type="script">
  Starts the Solid Queue supervisor on its own. Run it in a `job` role when `SOLID_QUEUE_IN_PUMA=false`. See [Scaling](/operate/scaling).
</ResponseField>

<ResponseField name="bin/kamal-parse" type="script">
  Reads Kamal configs with Kamal's own code, and prints what Meridian needs as JSON. That is the service, image, roles, accessories, hostnames, secret names and labels, or an error with its file and line.

  Meridian runs it in a separate process with an empty environment. It runs inside a temporary folder that holds only the files Meridian fetched from Git.

  ```bash
  echo '{"configs":[{"path":"config/deploy.yml","destination":null}]}' | bin/kamal-parse
  ```
</ResponseField>

<ResponseField name="bin/icons" type="script">
  Copies Lucide icons into `vendor/lucide`, all from one pinned Lucide release. With no arguments, it downloads every icon already in `vendor/lucide` again. With icon names, it adds those icons.

  ```bash
  bin/icons bell x
  ```
</ResponseField>

<ResponseField name="bin/docs" type="script">
  Runs the documentation site in `docs/` with Mintlify's command-line tool. It needs Node 20.17 or later.

  | Subcommand | What it does |
  | --- | --- |
  | `bin/docs` or `bin/docs dev` | Previews the site at `http://localhost:3333`. `PORT=` changes the port. |
  | `bin/docs check` | Runs what CI checks: `mint validate`, `mint broken-links` and `mint a11y`. |
  | `bin/docs changelog` | Writes `docs/changelog.mdx` from `CHANGELOG.md`. `bin/docs` also does this before every preview and check. Nobody commits the page. |
</ResponseField>

<ResponseField name="bin/lab" type="script">
  Runs a test fleet on your own machine: servers in Docker containers, an image registry and a self-hosted GitHub Actions runner. It deploys real sites from start to finish. See [`lab/README.md`](https://github.com/bigint/meridian/blob/main/lab/README.md).

  | Subcommand | What it does |
  | --- | --- |
  | `up owner/repo` | Starts the registry and servers, and registers the runner on the infra repository. Needs `gh`. |
  | `push SITE [VERSION]` | Builds a site from `ghcr.io/bigint/<site>` and pushes it to the lab registry. `all` pushes every site. `push umami VERSION` pushes an Umami release. |
  | `versions SITE` | Lists a site's published versions, as short commit IDs. |
  | `agents` | Builds the agent, creates a token per server and starts an agent on each, with `MERIDIAN_INTERVAL=5s` and `MERIDIAN_LOGS=1`. `MERIDIAN_URL` defaults to `http://host.docker.internal:3000`. |
  | `webhooks owner/repo` | Forwards the repository's webhooks to the dev server with `gh webhook forward`, until you stop it. |
  | `secrets owner/repo` | Sets the repository secrets the lab's `.kamal/secrets` reads, skipping any already set. |
  | `kamal owner/repo ARGS...` | Runs Kamal against a fresh clone of the infra repository, inside the lab network. |
  | `ssh [server]` | Opens a shell on a lab server. The default is `apse1-az1-node-01`. |
  | `status` | Lists the lab's containers, and the containers on each server. |
  | `down` | Stops the lab. |
</ResponseField>

The other files in `bin/` are the standard Rails and gem launchers: `bin/rails`, `bin/rake`, `bin/rubocop`, `bin/brakeman`, `bin/bundler-audit`, `bin/importmap` and `bin/thrust`. `bin/docker-entrypoint` is the script the image runs at start.

## Scripts in script

| Command | What it does |
| --- | --- |
| `ruby script/error_pages.rb` | Writes the static error pages in `public/` (`400`, `404`, `406-unsupported-browser`, `422`, `500`) and `public/error-pages.css`. |
| `bin/rails runner script/world_map.rb ne_110m_land.geojson` | Rebuilds `app/assets/images/world.svg` from Natural Earth's land outlines. |
| `ruby script/docs_changelog.rb` | Writes `docs/changelog.mdx` from `CHANGELOG.md`. `bin/docs` runs it. |

## The agent

| Command | What it does |
| --- | --- |
| `meridian-agent` | Runs the agent with the configuration in [Environment variables](/reference/environment#agent). |
| `meridian-agent -print` | Collects one snapshot, prints it as JSON and exits. It needs no URL or token. |

To run it inside a running agent accessory:

```bash
kamal accessory exec --reuse meridian_agent "/meridian-agent -print"
```

To build and test it:

```bash
cd agent
go vet ./... && go test ./...
docker build --build-arg VERSION=$(git rev-parse --short HEAD) -t meridian-agent .
```
