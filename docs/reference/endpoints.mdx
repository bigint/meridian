This page lists every address Meridian answers. Five are endpoints for machines. Everything else is an HTML page that needs you to be signed in, through the session cookie.

| Endpoint | Caller | Auth |
| --- | --- | --- |
| `POST /agent/snapshots` | The agent | `Authorization: Bearer <agent token>` |
| `POST /webhooks/github` | GitHub | `X-Hub-Signature-256` |
| `GET /cable` | The agent and browsers | Agent token, or the session cookie |
| `GET /up` | kamal-proxy and monitors | None |
| `/jobs` | Admins in a browser | The session cookie, admin role |

## POST /agent/snapshots

A snapshot: what runs on one server. The [agent](/reference/glossary#agent) sends one every 15 seconds by default. Meridian checks it, queues it, and answers `202`.

- Meridian refuses a body over 1 MiB with `413`, before Rails reads it.
- Each token can send 120 a minute.
- A fleet token can send 120 a minute for each machine ID, and 12,000 a minute in all.

See [Agent protocol](/reference/agent-protocol#snapshots) for the fields and every status code.

## POST /webhooks/github

Where GitHub sends [webhooks](/reference/glossary#webhook), the messages it sends when something changes. Meridian checks each one's HMAC-SHA256 signature against `GITHUB_APP_WEBHOOK_SECRET`. It queues `push`, `workflow_run` and `pull_request` events, and answers `202`.

- A bad signature, or no secret set, gets `401`.
- A body that is not JSON gets `400`.

See [GitHub App](/reference/github-app#webhook).

## GET /cable

Rails' Action Cable WebSocket, a connection that stays open so Meridian can push updates. Two kinds of client connect to it:

| Client | Auth | Channels |
| --- | --- | --- |
| The agent | `Authorization: Bearer <agent token>`. A connection with this header never falls back to a cookie. | `AgentChannel` |
| A browser | The signed `session_id` cookie | Turbo Streams for live pages, `ServerStatsChannel`, `LogsChannel`, `TrafficChannel` |

Live pages refresh through Turbo Streams: the board, the map, an app's page and previews. Stats, logs and traffic stream through their own channels.

Logs and traffic need the deployer role, plus a grant. The page creates that grant when it records the viewing in Activity. When a person's role changes or they sign out, Meridian closes their open connections.

See [Agent protocol](/reference/agent-protocol#the-live-line).

## GET /up

Rails' health check. It answers `200` when the app has started, and `500` when it failed to start.

- It needs no sign-in.
- It skips forced HTTPS and the `MERIDIAN_URL` host check.
- Meridian leaves it out of the logs.

[kamal-proxy](/reference/glossary#kamal-proxy) calls it by IP address before it sends traffic to a new container.

```bash
curl -fsS https://meridian.example.com/up
```

## /jobs

Mission Control Jobs, the dashboard for Meridian's background jobs in Solid Queue. It shows queues, running, failed and scheduled jobs, and recurring tasks.

Only admins can open it. Anyone else is sent back with **You don't have permission to do that.** The sidebar links to it as **Jobs**.

## Pages

Every other address is a page for people. The rate limits in the **What it is** column count requests from one IP address.

- A request from someone not signed in goes to `/session/new`.
- A request that needs a higher role is sent back with an alert. If it does not ask for HTML, it gets `403`.

| Path | What it is | Role |
| --- | --- | --- |
| `/` | The board | Viewer |
| `/jump?q=` | Search: apps, servers and projects, the best 8 | Viewer |
| `/map` | The map | Viewer |
| `/apps`, `/apps/:id` | Apps and an app's page | Viewer |
| `/apps/new` | New app | Admin |
| `POST /apps/:id/deploys` | Deploy a version. 10 a minute. | Deployer |
| `POST /apps/:id/rollbacks` | Roll back the newest release. 10 a minute. | Deployer |
| `POST /apps/:id/redeploy` | Run CI again for the version in Git. 5 a minute. | Deployer |
| `/apps/:id/log` | An app's logs, merged across its servers | Deployer |
| `/apps/:id/traffic` | An app's requests, from kamal-proxy | Deployer |
| `/placements/:id/log` | One container's logs | Deployer |
| `/servers`, `/servers/:id` | Servers and a server's page | Viewer |
| `PATCH /servers/:id` | Set a server's location | Admin |
| `/events` | Activity | Viewer |
| `/secrets` | Secret names per project | Viewer |
| `POST /secrets`, `PATCH /secrets/:id` | Add a name, set a value. 20 a minute. | Admin |
| `/previews` | Previews | Viewer |
| `POST /previews/:id/closure` | Destroy a preview: CI removes it, then Meridian drops its overlay | Deployer |
| `/tunnels`, `/tunnels/setup` | Tunnels and tunnel setup | Viewer |
| `/tunnels/connectors/edit` | Edit connectors | Admin |
| `/agents` | Agent tokens and silent servers | Viewer |
| `POST /agents`, `DELETE /agents/:id` | Create and revoke tokens | Admin |
| `/projects`, `/projects/:id` | Projects and a project's page | Viewer |
| `/projects/new`, `/projects/:id/edit` | Add and edit a project | Admin |
| `POST /projects/:id/sync` | Sync now | Admin |
| `POST /projects/:id/workflow` | Add CI workflow | Admin |
| `/settings`, `/settings/users` | Settings and People | Admin |
| `/session/new` | Sign in. 10 tries in 3 minutes. | None |
| `/first_run` | Create the first admin, with the setup code. Gone once a user exists. | None |

## No general API

Meridian has no REST or GraphQL API, and no API tokens for people. This is on purpose:

- Git is the interface for changes. To deploy from a script, commit the version file. Meridian sees the commit and CI deploys it, exactly as if someone pressed **Deploy**.
- Agent tokens work only on `/agent/snapshots` and `/cable`. They can't read or change anything else.
- Pages check the session cookie and a CSRF token, so another site can't drive them.
