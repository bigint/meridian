Drift is the difference between what Git says should run and what the agent on a server sees running. This page lists the six states a board cell can be in, and the exact rule that picks one.

## The idea

For every app on every server, Meridian compares the app's newest [release](/reference/glossary#release) in Git with the versions the [agent](/reference/glossary#agent) reports. The agent is a small read-only program on each server. Meridian works out the state each time a page asks, so it is never out of date.

<DriftStates />

## Examples

Take the app `shop`. Its version file says the newest release is `v42`.

| Git assigns | The agent reports | State |
| --- | --- | --- |
| `web` | `web` running `v42` | In sync |
| `web` | `web` running `v41` | Drifted |
| `web` | `web` running `v41` and `v42` | Drifted, during a rolling deploy |
| `web` and `job` | `web` running `v42`, no `job` | Missing, for the `job` role |
| nothing | `web` running `v42` | Stray |
| `web` | its last report came 2 minutes ago | Stale |
| `web` | never reported | Unknown |

If `shop` had no version file, the first three rows would be **unknown**, because there is nothing to compare with. The other rows keep their state.

## The rule

For one app, one server and one role, Meridian asks these questions in order. The first match gives the state.

<Steps>
  <Step title="Has the server's agent ever reported?">
    If not, the cell is **unknown** when Git assigns the app here. Otherwise there is no cell.
  </Step>
  <Step title="Has the agent gone quiet?">
    If so, the cell is **stale**, whatever Git or the last snapshot said.
  </Step>
  <Step title="Does Git assign this role here?">
    If not, the cell is **stray** when the role has running containers here. Otherwise there is no cell.
  </Step>
  <Step title="Is anything running?">
    If not, the cell is **missing**.
  </Step>
  <Step title="Does the app have a newest release to compare with?">
    If not, the cell is **unknown**. An app without a version file never has one.
  </Step>
  <Step title="Does every running container run the newest release?">
    If so, the cell is **in sync**. If not, it is **drifted**.
  </Step>
</Steps>

Only containers in the `running` state count. A container that exited, is restarting or is paused counts as nothing running.

A container belongs to an app when its Kamal labels `service` and `destination` match the app's. A container that matches no app in Meridian, such as one from a repository you haven't added, is not on the board.

<Accordion title="How this works under the hood">
  The code is `Drift.state` in `app/models/drift.rb`. It takes four inputs:

  - Whether Git assigns the role to the server.
  - The versions of that role's running containers, from the last snapshot.
  - The app's newest release.
  - When the server's agent last reported.
</Accordion>

## Roles and the worst state

An app often runs several roles on one server, such as `web` and `job`. Each role gets its own state, and the cell shows the worst one. So a stopped `job` container never hides behind a running `web` one.

From worst to best:

1. Missing
2. Drifted
3. Stray
4. Stale
5. Unknown
6. In sync

The map uses the same order for each place, and the **Needs attention** list sorts by it.

## Stale timing

An agent is quiet when its last snapshot is older than three of its intervals. It is never less than 45 seconds:

```text
stale after = max(3 × interval, 45 seconds)
```

The interval is the agent's `MERIDIAN_INTERVAL`, which each snapshot reports. Meridian assumes 15 seconds for an agent that doesn't send it.

| `MERIDIAN_INTERVAL` | Stale after |
| --- | --- |
| `15s`, the default | 45 seconds |
| `5s` | 45 seconds |
| `30s` | 90 seconds |
| `1m` | 3 minutes |

A stale cell is not a fault in the app. It says only that Meridian can't see the server right now. The server's page keeps the last snapshot's containers until the agent reports again.

<Accordion title="Edge cases">
  The agent moves each interval up to 20% earlier or later. Three intervals leave room for that and one lost snapshot, so a single late report doesn't flag a server.

  A quiet agent sends nothing, so nothing would redraw its cells. Once a minute, Meridian refreshes open pages for every quiet server. A cell turns stale within about a minute of crossing the line. The first snapshot after a silence redraws at once.
</Accordion>

## What drift doesn't tell you

- **Whether the app works.** In sync means the right version runs. The **Health** column on the app's page shows the containers' health checks.
- **Whether Git is right.** Meridian compares with the newest release it has read from Git. A new commit shows up within 30 seconds.
- **Anything about containers without Kamal labels.** The agent reports only containers that Kamal started, plus `kamal-proxy`.

## Needs attention

The board's **Needs attention** list turns missing, drifted, stray and stale cells into sentences, worst first. One quiet server is one item, however many apps run on it. The number next to **Board** in the sidebar counts this list, and refreshes at most every 15 seconds. See [Board and map](/guides/board-and-map).
