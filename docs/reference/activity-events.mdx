This page lists every event Meridian records. Each change Meridian makes, and each time someone reads logs or traffic, is an event on the **Activity** page (`/events`).

Meridian never edits or deletes an event. The page shows 50 at a time, newest first, grouped by day.

Each event keeps:

- **Action**, a dotted name such as `app.deploy`.
- **Who**, the user who acted. Events from webhooks and scheduled jobs have no user, so they show as **Meridian**. An event from a user who no longer exists keeps their name, marked `(removed)`.
- **Summary**, the sentence the page shows, such as `Deployed web · production to 3f2a9c1e`.
- **Details**, such as the commit, the version, the pull request URL or the files changed. The page links the commit and the pull request.

## Filter

**Action starts with** matches the start of the action name. `app.` shows every deploy, rollback and redeploy. `project.` shows every project change.

It is a URL parameter, so you can bookmark a filtered view: `/events?action_name=app.`.

## Apps

| Action | Recorded when | Details |
| --- | --- | --- |
| `app.deploy` | You press **Deploy** and Meridian commits the version file | `commit`, `version` |
| `app.rollback` | You press **Roll back** and Meridian commits the version from before the newest release | `commit`, `version` |
| `app.redeploy` | You press **Redeploy** and Meridian starts the [CI workflow](/reference/glossary#ci-workflow) | `version` |

A `git push` outside Meridian that changes a version file records no event. It shows on the app's page as a release, and as a deploy once CI runs.

## Projects

| Action | Recorded when | Details |
| --- | --- | --- |
| `project.created` | You add a project | |
| `project.updated` | You save a project's settings | |
| `project.removed` | You remove a project | |
| `project.pull_request` | Meridian opens a pull request for **New app**, **Add CI workflow** or **Edit connectors** | `pull_request`, `files` |
| `project.committed` | The same changes, committed directly because the project has **Direct commits** on | `commit`, `files` |

## Secrets

| Action | Recorded when |
| --- | --- |
| `secret.set` | You set or change a secret's value. Meridian never records the value. |

Adding a secret name without a value records no event.

## Logs and traffic

| Action | Recorded when |
| --- | --- |
| `logs.viewed` | You open an app's logs or one container's logs. The summary names the app or container, and how many containers and servers. |
| `traffic.viewed` | You open an app's **Traffic** page. The summary says how many servers' kamal-proxy Meridian reads. |

The page records the event before it streams anything. The logs and traffic channels stream only what a page recorded. So no one can read logs without leaving an event.

## Agents and servers

| Action | Recorded when |
| --- | --- |
| `agent_token.created` | You create an agent token. The summary gives its label. |
| `agent_token.revoked` | You revoke an agent token. |
| `server.located` | You set a server's latitude and longitude. |

## Account and settings

| Action | Recorded when |
| --- | --- |
| `user.updated` | You change your name, email address or password in **Settings**. The summary is `Updated your account`. |
| `settings.updated` | You save **Workspace** or **Where Meridian runs** in **Settings**. |

## Not recorded

These record no event:

- Signing in and out.
- Syncs, whether from a webhook, the 30-second poll or **Sync now**. The project page shows when it last synced and any parse errors.
- Deploy progress. The app's page shows each deploy's CI status, from `pending` to `completed`.
- Snapshots and live stats.

Git keeps its own record. Every commit Meridian makes for you ends in a `Meridian-Actor:` line that names you. See [Infra repository](/reference/infra-repository#commits).
