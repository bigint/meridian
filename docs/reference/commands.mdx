Run these from the root of a Meridian checkout, or inside the running container through Kamal.

## Kamal aliases

Meridian's `config/deploy.yml` defines two aliases:

| Command | Runs |
| --- | --- |
| `kamal console` | `kamal app exec --interactive --reuse "bin/rails console"`, a Rails console in the running container |
| `kamal logs` | `kamal app logs -f`, Meridian's log, followed |

Any task below runs in production the same way:

```bash
kamal app exec --reuse "bin/rails meridian:setup_code"
```

## Rake tasks

<ResponseField name="bin/rails meridian:setup_code" type="task">
  Prints the code that creating the first admin on `/first_run` asks for. The code is derived from `SECRET_KEY_BASE`, so it needs no storage. Meridian also logs it each time someone opens `/first_run`, as `Meridian setup code: …`.
</ResponseField>

<ResponseField name="bin/rails meridian:demo" type="task">
  Seeds a demo fleet with realistic drift: 500 servers and 200 apps by default. `SERVERS=` and `APPS=` change the sizes. It can run again over an existing demo fleet.

  ```bash
  bin/rails meridian:demo SERVERS=50 APPS=20
  ```
</ResponseField>

<ResponseField name="bin/rails db:prepare" type="task">
  Creates or migrates every database. The image's entrypoint runs it before the server starts. See [Upgrading](/operate/upgrading).
</ResponseField>

<ResponseField name="bin/rails test" type="task">
  Runs the Rails tests. `bin/rails test:system` runs the browser tests.
</ResponseField>

## Scripts in bin

<ResponseField name="bin/setup" type="script">
  Installs gems, prepares the database, clears logs and temporary files, then starts the development server. It is safe to run again.

  - `--skip-server` stops before the server.
  - `--reset` also resets the database.
</ResponseField>

<ResponseField name="bin/dev" type="script">
  Starts the development server, `bin/rails server`, on port 3000. Arguments pass through.
</ResponseField>

<ResponseField name="bin/ci" type="script">
  Runs every check a change must pass, as `config/ci.rb` lists them: setup, RuboCop, `bundler-audit`, the importmap audit, Brakeman, the Rails and system tests, and the agent's `go vet`, `staticcheck` and `go test -race`.
</ResponseField>

<ResponseField name="bin/jobs" type="script">
  Starts the Solid Queue supervisor on its own. Run it in a `job` role when `SOLID_QUEUE_IN_PUMA=false`. See [Scaling](/operate/scaling).
</ResponseField>

<ResponseField name="bin/kamal-parse" type="script">
  Parses Kamal configs with Kamal's own code and prints what Meridian needs as JSON: service, image, roles, accessories, hostnames, secret names and labels, or an error with its file and line. Meridian runs it in a separate process with an empty environment, inside a temporary folder that holds only the files fetched from Git.

  ```bash
  echo '{"configs":[{"path":"config/deploy.yml","destination":null}]}' | bin/kamal-parse
  ```
</ResponseField>

<ResponseField name="bin/icons" type="script">
  Vendors Lucide icons into `vendor/lucide`, pinned to one release. With no arguments, it downloads every icon already vendored again. With names, it adds those icons.

  ```bash
  bin/icons bell x
  ```
</ResponseField>

<ResponseField name="bin/docs" type="script">
  The documentation site in `docs/`, with Mintlify's CLI. Needs Node 20.17 or later.

  | Subcommand | What it does |
  | --- | --- |
  | `bin/docs` or `bin/docs dev` | Previews the site at `http://localhost:3333`. `PORT=` changes the port. |
  | `bin/docs check` | Runs what CI checks: `mint validate`, `mint broken-links` and `mint a11y`. |
  | `bin/docs changelog` | Writes `docs/changelog.mdx` from `CHANGELOG.md`, which `bin/docs` also does before every preview and check. The page is never committed. |
</ResponseField>

<ResponseField name="bin/lab" type="script">
  A local fleet: Docker-in-Docker servers, a registry and a self-hosted GitHub Actions runner, deploying real sites end to end on one machine. See [`lab/README.md`](https://github.com/bigint/meridian/blob/main/lab/README.md).

  | Subcommand | What it does |
  | --- | --- |
  | `up owner/repo` | Starts the registry and servers, and registers the runner on the infra repository. Needs `gh`. |
  | `push SITE [VERSION]` | Builds a site from `ghcr.io/bigint/<site>` and pushes it to the lab registry. `all` pushes every site. `push umami VERSION` pushes an Umami release. |
  | `versions SITE` | Lists a site's published versions, as short SHAs. |
  | `agents` | Builds the agent, creates a token per server and starts an agent on each, with `MERIDIAN_INTERVAL=5s` and `MERIDIAN_LOGS=1`. `MERIDIAN_URL` defaults to `http://host.docker.internal:3000`. |
  | `webhooks owner/repo` | Forwards the repository's webhooks to the dev server with `gh webhook forward`, until stopped. |
  | `secrets owner/repo` | Sets the repository secrets the lab's `.kamal/secrets` reads, skipping any already set. |
  | `kamal owner/repo ARGS...` | Runs Kamal against a fresh clone of the infra repository, inside the lab network. |
  | `ssh [server]` | Opens a shell on a lab server. The default is `apse1-az1-node-01`. |
  | `status` | Lists the lab's containers, and the containers on each server. |
  | `down` | Stops the lab. |
</ResponseField>

The other files in `bin/` are the standard Rails and gem binstubs: `bin/rails`, `bin/rake`, `bin/rubocop`, `bin/brakeman`, `bin/bundler-audit`, `bin/importmap` and `bin/thrust`. `bin/docker-entrypoint` is the image's entrypoint.

## Scripts in script

| Command | What it does |
| --- | --- |
| `ruby script/error_pages.rb` | Writes the static error pages in `public/` (`400`, `404`, `406-unsupported-browser`, `422`, `500`) and `public/error-pages.css`. |
| `bin/rails runner script/world_map.rb ne_110m_land.geojson` | Regenerates `app/assets/images/world.svg` from Natural Earth's land outlines. |
| `ruby script/docs_changelog.rb` | Writes `docs/changelog.mdx` from `CHANGELOG.md`. `bin/docs` runs it. |

## The agent

| Command | What it does |
| --- | --- |
| `meridian-agent` | Runs the agent with the configuration in [Environment variables](/reference/environment#agent). |
| `meridian-agent -print` | Collects one snapshot, prints it as JSON and exits. Needs no URL or token. |

Inside a running agent accessory:

```bash
kamal accessory exec --reuse meridian_agent "/meridian-agent -print"
```

To build and test it:

```bash
cd agent
go vet ./... && go test ./...
docker build --build-arg VERSION=$(git rev-parse --short HEAD) -t meridian-agent .
```
