Find what you see in the titles below. Each entry says why it happens, then how to fix it.

Two places help with most problems:

- `kamal logs` follows Meridian's log. For more detail, set `RAILS_LOG_LEVEL` to `debug`.
- `/jobs` lists failed jobs with their error. A failed sync shows there as a failed `ProjectSyncJob`.

## Setup and sign-in

<AccordionGroup>
  <Accordion title="The setup code doesn't match">
    `/first_run` says **doesn't match the one in Meridian's log**. Meridian makes the code from `SECRET_KEY_BASE`, and logs it each time someone opens `/first_run`. If you changed `SECRET_KEY_BASE` after that log line, the code changed with it.

    Get the current code with either command. The second one always gives the current code.

    ```bash
    kamal app logs | grep "setup code"
    kamal app exec --reuse "bin/rails meridian:setup_code"
    ```

    Once one user exists, `/first_run` sends you to the board.
  </Accordion>
  <Accordion title="Sign-in says Try again later">
    Sign-in allows 10 tries in 3 minutes from one address. Wait 3 minutes and try again.

    **Try another email address or password** means the email address or password is wrong. Once signed in, change your password under **Settings → Your account**.
  </Accordion>
  <Accordion title="The browser loops between http and https, or the page won't load">
    With an `https://` `MERIDIAN_URL`, Meridian sends every request to HTTPS. It expects a proxy in front of it to handle TLS. When nothing does, as when you try Meridian on a LAN, the page never loads.

    Set `MERIDIAN_URL` to the `http://` address.
  </Accordion>
  <Accordion title="Meridian answers 403 at an address that should work">
    In production, Meridian answers only to `MERIDIAN_URL`'s host. It blocks a request for any other host, such as the server's IP address or a second DNS name. `/up` answers on any host.

    Use the URL's host, or change `MERIDIAN_URL`.
  </Accordion>
  <Accordion title="The page says your browser is too old">
    Meridian needs a current Chrome, Edge, Firefox or Safari. It answers older browsers with a `406` page.

    Update the browser, or use one of those four.
  </Accordion>
</AccordionGroup>

## GitHub and sync

<AccordionGroup>
  <Accordion title="Settings says GitHub: Not connected">
    Meridian found no GitHub credentials in its environment. Actions fail with **GitHub isn't connected: set GITHUB_APP_ID and GITHUB_APP_PRIVATE_KEY, or GITHUB_TOKEN**.

    Set those variables in the container's environment and redeploy Meridian. See [Environment variables](/reference/environment#github).
  </Accordion>
  <Accordion title="A project shows no apps">
    Meridian hasn't synced the project yet, can't reach the repository, or finds no configs. Check these on the project's page, in order:

    1. **Synced** shows a commit. **never** means no sync has finished yet. Look in `/jobs` for a failed `ProjectSyncJob`, then press **Sync now**.
    2. With the GitHub App, the project has the right **GitHub App installation ID**, and the App is installed on that repository.
    3. **Configs** match your files. The default, `config/deploy*.yml`, doesn't find `deploy/web.yml`. Only files ending in `.yml` or `.yaml` count.
    4. **Parse errors** lists no error for the config.

    When you save new config paths, Meridian syncs at once. See [Choose config paths](/guides/projects#choose-config-paths).
  </Accordion>
  <Accordion title="The project page lists parse errors">
    Kamal couldn't read a config. Each error gives the file and line, with a link to it on GitHub. Until the config parses again, its app stays as it was, with its deploys and releases.

    Fix the config in Git and push. The next sync clears the error. See [Fix parse errors](/guides/projects#fix-parse-errors).

    Three errors stop the whole project, not one config:

    - **Parsing timed out after 60 seconds**. ERB in a config ran too long.
    - **Parser failed**, followed by the parser's last lines. ERB crashed the parser.
    - **The parser exited without a result**.

    Meridian tries the same commit again after 1 minute, then waits twice as long each time, up to once an hour. A new commit or **Sync now** tries at once.
  </Accordion>
  <Accordion title="The sync fails with GitHub truncated the tree">
    The full message is **GitHub truncated the tree of `<sha>`: the repository has too many files to read**. GitHub cuts a file list short above about 100,000 files. Meridian stops rather than read part of it, because the missing configs would look deleted.

    Keep the Kamal configs in a smaller repository.
  </Accordion>
  <Accordion title="A secret named GITHUB_… is missing from the Secrets page">
    GitHub can't store secrets whose names start with `GITHUB_`, so Meridian leaves them off the **Secrets** page. The rest of the project syncs.

    Rename the secret in the config.
  </Accordion>
  <Accordion title="Pushes and CI runs show up late">
    GitHub's [webhooks](/reference/glossary#webhook) don't reach Meridian. Meridian still checks each project every 30 seconds, so pushes and CI runs show up within 30 seconds.

    - **Settings → Connections** says **Webhooks: Off**. Set `GITHUB_APP_WEBHOOK_SECRET`.
    - In the App's settings, **Advanced → Recent Deliveries** shows each delivery and Meridian's answer. `401` means the secret in GitHub and `GITHUB_APP_WEBHOOK_SECRET` differ. `400` from a repository webhook means its content type isn't `application/json`.
    - No answer at all means GitHub can't reach Meridian. A Meridian on a private network gets no webhooks unless you forward them to it.

    See [GitHub App](/reference/github-app#webhook).
  </Accordion>
</AccordionGroup>

## Agents

Read the [agent](/reference/glossary#agent)'s log on the server first:

```bash
kamal accessory logs meridian_agent
```

<AccordionGroup>
  <Accordion title="A server never appears, or shows as never seen">
    The agent on that server never reported. The **Agents** page lists such servers under **Silent agents**. Find the agent's log line below:

    | Log line | Why, and the fix |
    | --- | --- |
    | `invalid configuration` with `MERIDIAN_URL is required` or `MERIDIAN_TOKEN is required` | The variable is missing, and the agent exits with code 2. Set it. |
    | `no machine id` | The agent can't read the machine ID. Mount `/etc/machine-id:/host/etc/machine-id:ro`, or set `MERIDIAN_MACHINE_ID`. |
    | `snapshot failed` with `docker:` | The agent can't reach Docker. `DOCKER_HOST` must name `<service>-meridian_docker` on port `2375`, with the config's real service. Both accessories must be on the `meridian` network. To mount the socket directly instead, give the agent the host's docker group, because the image runs as uid 65532. |
    | `snapshot failed` with `post snapshot:` and a network error | The server can't reach `MERIDIAN_URL`. Use an address the server itself can reach, not a container name on Kamal's network. |
  </Accordion>
  <Accordion title="The token shows Last used, but the server has no cells">
    The agent reports, but Git and the agent name the server differently. Git uses the host Kamal connects to over SSH. The agent reports the machine's own hostname. Meridian matches them exactly, or by the first DNS label when only one server has it. IP addresses must match whole.

    Find the agent's server under **Servers**, and compare its hostname with the host in your config. Set `MERIDIAN_HOSTNAME` on the agent to the host your config uses, then reboot the agent. See [Matching servers to Git](/guides/agent#matching-servers-to-git).
  </Accordion>
  <Accordion title="One machine shows as two servers">
    Same cause as above: Git and the agent name the machine differently, so Meridian can't match them. Set `MERIDIAN_HOSTNAME` on the agent to the host your config uses.

    A machine rebuilt with a new machine ID takes over its old server once the old agent has been silent for 10 minutes.
  </Accordion>
  <Accordion title="The agent logs unexpected status 401">
    Meridian doesn't know the token, or someone revoked it. Meridian shows a token only once, so you can't get it back.

    Create a new token on the **Agents** page, put it in `.kamal/secrets` as `MERIDIAN_TOKEN`, and reboot the agent accessory.
  </Accordion>
  <Accordion title="The agent logs 422: This token belongs to another server">
    A per-server token binds to the first server that reports with it, and a second machine is using it.

    Give each server its own token, or create a token with **Fleet token, shared by many servers** ticked. See [One token per server, or one for the fleet](/guides/agent#one-token-per-server-or-one-for-the-fleet).
  </Accordion>
  <Accordion title="The agent logs 429">
    The agent sent too many snapshots. Meridian allows 120 a minute per token. A fleet token gets 120 a minute for each server, up to 12,000 a minute for the whole token. The agent waits as long as `Retry-After` says, then carries on.

    One agent can't reach this limit on its own. It sends one snapshot per `MERIDIAN_INTERVAL`, which is at least 1 second, so at most 60 a minute.

    A 429 means one of two things. Several machines report with one per-server token. Or a fleet token sends more than 12,000 a minute, which is 3,000 servers at the default 15 seconds. Give each server its own token, or split a very large fleet across fleet tokens.
  </Accordion>
  <Accordion title="Cells turn stale">
    Meridian got no snapshot for three of the agent's intervals, and at least 45 seconds. A stopped agent, a server that lost its route to Meridian, and a revoked token all look the same here.

    Read the agent's log. If many servers go stale at once while their agents run, look at Meridian instead. On `/jobs`, a long `snapshots` queue means Meridian is falling behind. See [Scaling](/operate/scaling).
  </Accordion>
  <Accordion title="The server page stays at Connecting…">
    The agent's WebSocket, its open connection to `/cable`, doesn't reach Meridian.

    Check that `MERIDIAN_LIVE` isn't `0`. Check that every proxy between the agent and Meridian passes WebSockets through to `/cable`.
  </Accordion>
  <Accordion title="Live stats, logs or traffic stay empty">
    Find the line that matches, and do what it says:

    - The agent runs with `MERIDIAN_LIVE=0`. Remove it.
    - The agent can't open `/cable`, and its log says so on each try. Make the proxy in front of Meridian pass WebSocket upgrades.
    - The server hasn't sent a snapshot yet. Meridian refuses the live connection until the first one arrives.
    - Host numbers are missing. Mount `/proc:/host/proc:ro`.
    - Logs say they are off. Run the agent with `MERIDIAN_LOGS=1`. Logs follow only Kamal's containers, at most 20 at once.
  </Accordion>
</AccordionGroup>

## Deploys

<AccordionGroup>
  <Accordion title="A deploy stays Pending">
    Meridian committed the [version file](/reference/glossary#version-file). The deploy waits for a run of `meridian-deploy.yml` at that commit, and no run has started. Look for the cause that fits:

    - The infra repository has no [CI workflow](/reference/glossary#ci-workflow) on the project's branch. Press **Add CI workflow** on the project's page, and merge the pull request.
    - Someone renamed the workflow file. Meridian tracks only `meridian-deploy.yml`.
    - The workflow's `push` trigger doesn't cover the branch or `**/*.version`.

    Without webhooks, a run shows up within 30 seconds of starting. See [CI workflow](/reference/ci-workflow).
  </Accordion>
  <Accordion title="The deploy's CI run fails">
    Open the run from the deploy's CI link, and find which cause fits:

    - The repository has no `KAMAL_SSH_PRIVATE_KEY` or `KAMAL_REGISTRY_PASSWORD` secret.
    - Your config names a secret that isn't set on the **Secrets** page.
    - The registry has no image with that tag.
    - GitHub's runners can't reach your servers. Set the repository variable `MERIDIAN_RUNS_ON` to a self-hosted runner.
  </Accordion>
  <Accordion title="The version file changed in Git since this page loaded">
    Someone changed the version file after Meridian read it. Meridian refuses to overwrite their change, and reads the file again.

    Reload the page, check the new state, and try again.
  </Accordion>
  <Accordion title="GitHub refused the commit">
    GitHub turned the commit away, for example because of branch protection or a repository rule on the project's branch. Meridian shows GitHub's message.

    Let the App commit to the branch, or use a branch without that rule.
  </Accordion>
  <Accordion title="Deploy is refused">
    | Message | Why, and the fix |
    | --- | --- |
    | **`<version>` is already in `<file>`. Use Redeploy to run it again.** | The commit would change nothing, so CI would never run. Press **Redeploy**. |
    | **Version must be an image tag** | A [version](/reference/glossary#version) is a Docker tag: letters, digits, `_`, `.` and `-`, not starting with `.` or `-`. |
    | **only runs accessories** | The config is labelled `meridian.kind: accessories`. Start its accessories with `kamal accessory boot`. |
  </Accordion>
  <Accordion title="Roll back or Redeploy is refused">
    | Message | Why, and the fix |
    | --- | --- |
    | **Only the newest release can be rolled back** | Roll back reverts one [release](/reference/glossary#release), the newest. Deploy an older version instead. |
    | **`<file>` changed after `<sha>`** | Git has a newer release than Meridian synced. Reload and try again. |
    | **Nothing to roll back to** | The release created the version file, so there is no earlier version. Deploy one. |
    | **has no version file yet: deploy a version first** | Redeploy runs the version in the version file, and there is none. Deploy a version. |
    | **has no meridian-deploy.yml workflow** | The repository has no CI workflow. Add it first. |
  </Accordion>
  <Accordion title="The deploy succeeded but cells stay drifted">
    [Drift](/reference/glossary#drift) compares Git's version with what agents report. A cell stays drifted while any container of that app on that server runs another version. When Git assigns a role there and nothing runs, the cell shows missing instead.

    Open the server's page to see each container. Kamal names containers after the version, so the version in the file must be the image tag Kamal deployed.
  </Accordion>
</AccordionGroup>

## Secrets

<AccordionGroup>
  <Accordion title="A secret name is refused">
    A name must use capital letters, digits and `_`, start with a letter or `_`, and not start with `GITHUB_`. Meridian turns what you type into capitals.

    Change the name to fit.
  </Accordion>
  <Accordion title="A new secret value doesn't reach the app">
    Kamal reads secrets only when it deploys.

    After you set a value, press **Redeploy** on each app that uses it.
  </Accordion>
</AccordionGroup>
