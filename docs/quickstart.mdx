In two minutes you will have Meridian running in Docker, with a demo fleet that has real drift on it. Nothing connects to GitHub or to your servers. You need Docker.

<Steps>
  <Step title="Start Meridian">
    ```bash
    docker run -d --name meridian -p 3000:80 \
      -v meridian:/rails/storage \
      -e SECRET_KEY_BASE=$(openssl rand -hex 64) \
      -e MERIDIAN_URL=http://localhost:3000 \
      ghcr.io/bigint/meridian:v0.1.0
    ```

    The `meridian` volume holds the SQLite databases. `MERIDIAN_URL` is the address you open Meridian at. A plain `http://` URL turns off the HTTPS redirect, which you want on your own machine.
  </Step>

  <Step title="Create the first admin">
    Open [localhost:3000](http://localhost:3000). Meridian shows **Welcome to Meridian** and asks for a **Setup code**. Opening the page writes the code to the container's log:

    ```bash
    docker logs meridian 2>&1 | grep "setup code"
    ```

    ```text Output
    Meridian setup code: 3e1f0c9a8b7d6e5f4a3b
    ```

    Paste it in, add your name, an email and a password of at least 12 characters, and press **Create admin**. Meridian signs you in and opens **Projects**.

    <Tip>
    `docker exec meridian bin/rails meridian:setup_code` prints the same code.
    </Tip>
  </Step>

  <Step title="Seed a demo fleet">
    ```bash
    docker exec meridian bin/rails meridian:demo
    ```

    ```text Output
    Seeded Demo fleet: 500 servers, 200 apps. Open the board to look around.
    ```

    The demo adds a project called **Demo fleet** with 200 apps on 500 servers in eight regions, from `ams` to `tor`. Each app has three releases, `v10` to `v12`. Most servers run `v12`. Some run `v11` or nothing, a few apps run where Git doesn't put them, and a few servers have quiet agents. Every name is under `example.com`.

    For a smaller fleet, set `SERVERS` and `APPS`:

    ```bash
    docker exec -e SERVERS=40 -e APPS=12 meridian bin/rails meridian:demo
    ```

    Running the task again replaces the demo fleet.
  </Step>

  <Step title="Look around">
    Open **Board** in the sidebar, and try these in order:

    1. **Needs attention** lists what is wrong, worst first, in plain sentences. Each item has a button, such as **Open atlas-0**, that takes you to the app or server.
    2. Under **Every app on every server**, press a state chip such as **Drifted** to show only those cells. Press it again to show all.
    3. Click an app's name in the grid. The inspector opens on the right with its servers, its last three releases and a **Ship a version** box.
    4. Switch **Apps × servers** to **Servers × apps** to turn the grid around. With more than 30 servers, the grid groups them by region.
    5. Open **Map**. Each dot is a place, coloured by the worst state there, with lines between places that run the same apps. Click a dot to see its servers on the right.
    6. Type `atlas` in the search box at the top and press <kbd>Enter</kbd> to jump to the first match.

    The [tour](/tour) covers every page.
  </Step>
</Steps>

## What the demo can't do

The demo fleet has no agents and no GitHub behind it, so a few things behave differently from a real install:

- About a minute after you seed it, every server turns **stale**. Its agents were never real, and Meridian calls a server stale once its agent has been silent for 45 seconds. Run `meridian:demo` again to bring the drift back.
- **Deploy**, **Redeploy** and **Roll back** fail, because they commit to the demo's repository, `example/fleet`, through GitHub.
- **Settings** shows GitHub as **Not connected**.

## Clean up

```bash
docker rm -f meridian
docker volume rm meridian
```
