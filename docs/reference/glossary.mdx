This page explains each word Meridian's pages use. Each entry is a sentence or two, with a link to the page that covers it in full.

## Accessories-only config

A config labelled `meridian.kind: accessories`, such as a tunnel's edge config. It runs no app, so the board leaves it out and Meridian never deploys it. See [Infra repository](/reference/infra-repository#labels).

## Accessory

A Kamal accessory: a database, a cache or a tunnel connector that a config runs beside its app. An app's page lists its accessories, their state and the command that starts each one.

## Activity

The page that lists every event: each change Meridian made, and who asked for it. See [Activity events](/reference/activity-events).

## Agent

A small program on each server that tells Meridian what is running there. It only reads, and it only connects out to Meridian. Its name is `meridian-agent`. See [Servers and agents](/concepts/servers-and-agents).

## Agent token

The secret an agent sends to prove who it is. A per-server token belongs to the first server that reports with it, and a fleet token works on many servers. Meridian stores only a SHA-256 hash of each token.

## App

One config plus one destination. A config with no destinations is one app. Its name is the service, plus `· <destination>` when it has one, as in `web · production`. See [Apps and destinations](/concepts/apps-and-destinations).

## Assignment

Git saying that an app runs on a server, in a given Kamal role. Assignments come from configs.

## Board

The home page. It shows every app on every server, and each cell shows the version that runs there and its drift state. See [Board and map](/guides/board-and-map).

## CI workflow

The GitHub Actions workflow `.github/workflows/meridian-deploy.yml`. It runs Kamal when a version file changes. See [CI workflow](/reference/ci-workflow).

## Config

A Kamal file, such as `config/deploy.yml`, that says what an app is and which servers run it. It lives in the infra repository. See [Infra repository](/reference/infra-repository).

## Config paths

A project's file patterns that say which files are configs. The default is `config/deploy*.yml`. See [Infra repository](/reference/infra-repository#config-paths).

## Connector

A `cloudflared` accessory that runs a Cloudflare Tunnel on one server. See [Cloudflare Tunnel](/guides/cloudflare-tunnel).

## Deploy

To deploy, Meridian writes a version to an app's version file, and CI sees the commit and runs `kamal deploy`. A deploy is also the record of that rollout, with its CI status: `pending`, `queued`, `in_progress` or `completed`. See [Deploy](/guides/deploy).

## Destination

A variant of a config, such as `staging` or `production`, kept in a file like `config/deploy.staging.yml`. Kamal reads it with `-d <destination>`, and each destination is its own app. See [Apps and destinations](/concepts/apps-and-destinations).

## Direct commits

A project setting. When it is on, Meridian commits your changes to the branch instead of opening pull requests.

## Drift

The difference between what Git says should run and what the agent sees running. Meridian works it out each time and never stores it. See [Drift](/concepts/drift).

## Edge config

The accessories-only config that runs a tunnel's connectors. With the default config paths it is `config/deploy-edge.yml`. Otherwise it goes wherever the config paths put it.

## Event

One entry on the Activity page.

## Fleet token

An agent token that works on any number of servers. Meridian tells those servers apart by their machine ID.

## Infra repository

The Git repository that holds your Kamal configs. Meridian reads it and writes to it. See [Infra repository](/reference/infra-repository).

## Kamal

A tool that deploys apps as Docker containers to your own servers over SSH. Meridian never deploys with Kamal itself. Your CI workflow runs it. See the [Kamal docs](https://kamal-deploy.org).

## kamal-proxy

Kamal's web proxy on each server. It sends each request to the right app. Meridian reads its request log to show **Traffic**. See [Traffic](/guides/traffic).

## Kind

What an app is built with: `static`, `node`, `rails` or `other`, from the `meridian.kind` label. **New app** uses it to pick a port and a Dockerfile.

## Label selector

The labels a server needs to have, such as `role=web`. **New app** uses one to pick servers.

## Labels

Key and value pairs an agent reports for its server, such as `region=sgp`. They come from `MERIDIAN_LABELS`, and the board groups and filters by them. Configs have labels too: `meridian.kind` and `meridian.source`.

## Live line

The WebSocket connection an agent keeps open to `/cable`. Live stats, logs and traffic travel over it. See [Agent protocol](/reference/agent-protocol#the-live-line).

## Live stats

A server's CPU, memory, load and disk, and each container's, sent every second while its page is open. Meridian never stores them. See [Live stats and logs](/guides/live-stats-and-logs).

## Machine ID

A host's ID that never changes, read from `/etc/machine-id`. Meridian tells servers apart by it.

## Map

The page that shows servers on a world map. Servers close together share one place.

## Meridian-Actor

A line at the end of every commit Meridian makes for you. It names who asked for the change. See [Infra repository](/reference/infra-repository#commits).

## Needs attention

The board's list of cells that are missing, drifted, stray or stale, most urgent first. Each one is a plain sentence.

## Never seen

A server that Git lists but whose agent has never reported. The **Agents** page lists these servers.

## Place

A spot on the map. Servers within 60 km of each other share one place. It is also the name of where Meridian itself runs, set in **Settings**.

## Placement

A container that an agent reports on a server. Meridian replaces a server's placements with each new snapshot.

## Project

One infra repository added to Meridian. It has a branch, config paths and a GitHub App installation. See [Projects](/guides/projects).

## Proposal

A pull request that Meridian opens for **New app**, **Add CI workflow** or **Edit connectors**. Its branch is named `meridian/<slug>-<hex>`.

## Redeploy

Running CI again for the version already in the version file, for example after a secret changed. Meridian starts the workflow and changes no file.

## Region

The `region` label. The board groups servers by it when there are more than 30 servers, or when more than one region is in use.

## Release

A commit that changed an app's version file. Meridian names it by the version it wrote. With no version file, a release is a commit to the config, named by its short commit ID (SHA). See [Versions and releases](/concepts/versions-and-releases).

## Role

Kamal's name for a group of servers in a config, such as `web` or `job`. Meridian gives each role on a server its own drift state, and the cell shows the worst one. Meridian has no user roles: its one user can do everything. See [Drift](/concepts/drift#roles-and-the-worst-state).

## Roll back

Undoing the newest release: the version file goes back to what it held before. You can roll back only the newest release.

## Secret name

The name of a secret that a config uses in `env.secret` or `registry.password`. The **Secrets** page lists names, and the values go to GitHub and are never shown. See [Secrets](/guides/secrets).

## Server

A host that Git lists, that an agent reports, or both.

## Service

A config's `service:` value, the name Kamal gives its containers.

## Setup code

The code `/first_run` asks for before it creates your account. Find it in Meridian's log, or print it with `bin/rails meridian:setup_code`.

## Silent

A server whose agent has gone quiet for three of its intervals, and for at least 45 seconds. Its cells turn stale.

## Snapshot

What one agent saw on one server at one moment. The agent sends it to `POST /agent/snapshots`. See [Agent protocol](/reference/agent-protocol#snapshots).

## Source repository

The repository an app is built from, named by the `meridian.source` label. The app's page shows it.

## Sync

Meridian reading a project's configs and version files from Git. It runs every 30 seconds, when you press **Sync now**, and when you save new project settings.

## Tail lease

A 30-second request from Meridian asking an agent to follow one container's logs. Meridian renews it while someone is reading them.

## Traffic

An app's requests, read live from kamal-proxy on every server the app runs on. See [Traffic](/guides/traffic).

## Tunnel

A Cloudflare Tunnel that serves apps through connectors on your servers. See [Cloudflare Tunnel](/guides/cloudflare-tunnel).

## Version

The name of the build to run, such as `v42` or a commit SHA. It is a Docker image tag, and it is the one line in a version file. See [Versions and releases](/concepts/versions-and-releases).

## Version file

A one-line file next to a config, such as `config/deploy.version`, that holds the version to run. Meridian deploys by changing it. Its name is `<config>[.<destination>].version`. See [Infra repository](/reference/infra-repository).

## Watch lease

A 30-second request from Meridian asking an agent to stream live stats. Meridian renews it while someone has the server's page open.

## Workspace

The name of this Meridian install, set in **Settings**.
