Meridian stores settings in two places: the **Settings** page, for the whole install, and each project's own fields. Keys, URLs and tuning are environment variables instead. See [Environment variables](/reference/environment).

## The Settings page

**Settings** (`/settings`) is one page. **Workspace** and **Where Meridian runs** save together with **Save**, and Activity records `settings.updated`. **Your account** has its own **Save account** button.

### Workspace

<ResponseField name="Name" type="text" default="Meridian" required>
  The install's name.
</ResponseField>

### Where Meridian runs

Where Meridian itself sits on the map. The map centres its flows on this place: agent reports arrive here, and deploys go out from here.

<ResponseField name="Place" type="text">
  A name for the place, such as `Singapore`.
</ResponseField>

<ResponseField name="Latitude" type="number">
  From -90 to 90.
</ResponseField>

<ResponseField name="Longitude" type="number">
  From -180 to 180.
</ResponseField>

### Your account

Your own sign-in details. Meridian has one account, the one you made at first run.

<ResponseField name="Name" type="text">
  Your name. Activity and the `Meridian-Actor:` trailer on Meridian's commits use it. When blank, they use your email address.
</ResponseField>

<ResponseField name="Email" type="email" required>
  The address you sign in with.
</ResponseField>

<ResponseField name="New password" type="password">
  From 12 to 72 characters. Leave it blank to keep the current one. A new password signs you out of every other session, and keeps you signed in here.
</ResponseField>

Click **Save account**, and Activity records `user.updated` as **Updated your account**.

### Connections

The **Connections** card shows what Meridian read from its environment variables. Meridian doesn't store it. To change it, change the variables.

| Connection | Shows |
| --- | --- |
| GitHub | **App** and its ID, **Token** when only `GITHUB_TOKEN` is set, or **Not connected** |
| Webhooks | **On** when `GITHUB_APP_WEBHOOK_SECRET` is set. **Off** means Meridian polls GitHub every 30 seconds instead. |
| Kamal | The Kamal version Meridian parses configs with, `2.12.0` in this release |

## Project settings

Each [project](/reference/glossary#project) is one infra repository. Add one under **Projects → Add project**, and change it with **Edit** on the project's page. See [Projects](/guides/projects).

<ResponseField name="Name" type="text" required>
  The project's name in Meridian.
</ResponseField>

<ResponseField name="Repository" type="text" required>
  The GitHub repository that holds your Kamal configs, as `owner/name`. Each repository can be one project only, and case doesn't matter.
</ResponseField>

<ResponseField name="Branch" type="text" default="main" required>
  The branch Meridian reads and commits to. Meridian ignores pushes to other branches.
</ResponseField>

<ResponseField name="GitHub App installation ID" type="number">
  The App installation Meridian reads the repository through. It is the number at the end of the URL GitHub shows after you install the App. Leave it blank if Meridian uses a token. See [GitHub App](/reference/github-app#installation-id).
</ResponseField>

<ResponseField name="Config paths" type="text" default="config/deploy*.yml" required>
  File patterns, separated by commas, that say which files are Kamal configs. A file named `x.<destination>.yml` is the `<destination>` destination of `x.yml` or `x.yaml`, when both match. As in Kamal, only `.yml` destination files count. **New app** writes new configs at the first pattern with exactly one `*`. See [Infra repository](/reference/infra-repository#config-paths).
</ResponseField>

<ResponseField name="Direct commits" type="checkbox" default="off">
  **Commit changes directly instead of opening pull requests.** When on, **New app**, **Add CI workflow** and **Edit connectors** commit to the branch. When off, each opens a pull request. Deploys and rollbacks are always commits.
</ResponseField>

A new repository, branch, installation ID or config paths syncs the project as soon as you save. Other changes wait for the next push, or for the check Meridian makes every 30 seconds.

The project's page also has **Sync now**, **Add CI workflow**, **Parse errors** and, on its **Edit** page, **Remove project**. [Projects](/guides/projects) explains each one.
