A server's page shows its CPU, memory, load and disk once a second while you look at it. A logs page shows a container's log lines, or an app's lines from every server, as they are written. Both come from the [agent](/reference/glossary#agent) on each server, flow only while a page is open, and are never stored.

## Live stats

Open a server from **Servers**, the board, or the map. Its page has two live parts, **Host** and **Containers**.

<Frame>
  <img className="block dark:hidden" src="/screenshots/server.png" alt="A server page with live host tiles above the apps and containers tables" />
  <img className="hidden dark:block" src="/screenshots/server-dark.png" alt="A server page with live host tiles above the apps and containers tables" />
</Frame>

**Host** has four tiles:

| Tile | Value | Out of |
| --- | --- | --- |
| **CPU** | Percent busy | the host's cores |
| **Memory** | Bytes in use, and the share | total memory |
| **Load** `1m` | The one-minute load average | the host's cores |
| **Disk** | Bytes used on the host's root filesystem, and the share | its size |

Each tile has a small chart and `avg · peak` over the last 120 frames, about two minutes. A tile turns amber at 75% of its capacity and red at 90%.

**Containers** lists every container with Kamal labels, as the agent last reported it. Each running container gets live **CPU**, **Memory**, and **Network** in and out per second. Hover a value for the exact figure, such as the cores in use or the container's memory limit.

The pill next to **Host** shows the stream's state:

| Pill | Means |
| --- | --- |
| `Connecting…` | The page is connecting, or no frame has come yet. |
| `Live` | Frames are arriving. |
| `Paused, the agent stopped sending` | No frame for 5 seconds. |

### If the tiles stay empty

| Note under the tiles | Fix |
| --- | --- |
| `Host numbers need the agent's /proc mount.` | The agent can't read the host's `/proc`, so it sends only container numbers. Mount `/proc:/host/proc:ro` on the agent. The accessory template on the **Agents** page does this. |
| `Nothing yet. The agent needs a version with live stats and a reachable /cable.` | No frame came in 15 seconds. Check three things: the agent is a version with live stats, `MERIDIAN_LIVE` isn't `0`, and your proxy passes WebSockets through to Meridian's `/cable`. |

## Logs

### Turn logs on

Logs are off until you turn them on in each agent. Set `MERIDIAN_LOGS: 1` in the agent's accessory:

```yaml config/deploy.yml
  meridian_agent:
    env:
      clear:
        MERIDIAN_LOGS: 1
```

Then reboot the accessory with `kamal accessory reboot meridian_agent`. The accessory template on the **Agents** page sets `MERIDIAN_LOGS: 1` already. Remove the line to keep a server's logs off Meridian. `MERIDIAN_LIVE=0` turns logs off too, because logs use the same connection as live stats. See [Install the agent](/guides/agent).

### Open logs

<Steps>
  <Step title="Pick what to read">
    - **One container**: on a server's page, click the logs icon at the end of the container's row in **Containers**.
    - **One app, every server**: on an app's page, click **Logs**. The page merges up to 20 of the app's containers, from every server, running ones first.
  </Step>
  <Step title="Read">
    Each container starts with its last 200 lines, then new lines as they are written. Lines from several containers are merged by time. Each line has a coloured chip for its container.
  </Step>
</Steps>

The bar above the lines has:

- **Filter lines**: show only lines that contain the text, with each match marked.
- **Both**, **stdout** and **stderr**: pick the streams.
- **Wrap**: wrap long lines, or scroll them.
- **Follow**: stay at the newest line. Scroll up and the page holds still, and a button counts the new lines below.
- **Clear**: empty the page.
- On an app's page, one chip per container. Click a chip to hide or show that container's lines.

A JSON line shows its level, message and first fields. Click it for the rest. The page keeps the newest 5,000 lines and drops older ones.

The status at the end of the bar reads:

| Status | Means |
| --- | --- |
| `Connecting…` | The page is connecting. |
| `Live` | Lines are arriving. |
| `Waiting for new lines` | No new line for 10 seconds. |
| `Not streaming` | No container on the page will stream. |
| `Stopped: reload the page to keep reading` | The page was open more than 12 hours, so Meridian turned it down when it reconnected. Reload it. |

Notices appear among the lines:

| Notice | Means |
| --- | --- |
| `Logs are off on web-1's agent. Set MERIDIAN_LOGS=1 there to turn them on.` | That agent doesn't have logs turned on. See [Turn logs on](#turn-logs-on). |
| `Logs refused: ...` | The agent won't follow that container, and says why. It follows only Kamal's containers, never its own, and at most 20 at a time. |
| `120 lines skipped: logged faster than the agent sends` | The container logged more than 512 KB in a second, or more than 500 live lines in 250 ms. The number is how many lines were dropped. |
| `Container stopped` | The container is no longer running. |

The agent itself checks every container it is asked for against Kamal's labels. So even a Meridian that someone has taken over can't read the logs of anything else on the host.

## How the stream works

The agent keeps one WebSocket open to Meridian's `/cable`. It connects out to Meridian, with the same token as its reports. It streams only while a page asks for it, in 30-second turns that the page keeps renewing.

<Accordion title="How this works under the hood">
  <Steps>
    <Step title="You open the page">
      Meridian sends the server's agent a lease, a time-limited request to stream. A server page asks for 30 seconds of stats. A logs page asks for 30 seconds of one container's logs, starting with the last 200 lines.
    </Step>
    <Step title="The agent streams">
      Stats go out once a second. Log lines go out in batches, at most one batch per container every 250 ms. Meridian passes each one on to the open pages.
    </Step>
    <Step title="The page renews">
      Every 10 seconds the page tells Meridian it is still open, and Meridian renews the lease. It renews only for a page it has heard from in the last 75 seconds.
    </Step>
    <Step title="You leave">
      The lease runs out, and the agent stops within 30 seconds. If the page went to sleep or lost its network, the agent stops within about two minutes.
    </Step>
  </Steps>

  Limits keep the stream small:

  - The agent caps any lease at 120 seconds, whatever Meridian asks for.
  - Meridian drops stats frames that come faster than two a second.
  - The agent follows at most 20 containers at once and cuts lines at 8 KB.
  - The agent sends at most 512 KB a second per container. Each line counts 64 bytes on top of its text, so even blank lines are limited.
  - A logs page's grant to stream lasts 12 hours. After that, Meridian turns the page down the next time it reconnects.

  The message format is in [Agent protocol](/reference/agent-protocol).
</Accordion>

## Nothing is stored

Meridian passes stats and log lines on to the open pages and keeps them nowhere else. They go through the cable database, which keeps each message for about a minute. Leave the page, and the lines are gone.

Meridian does store the fact that you looked. Each time you open a logs page, Activity records `logs.viewed`, with who, and which container or app. See [Activity](/guides/activity).
