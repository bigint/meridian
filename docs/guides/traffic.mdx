An app's **Traffic** page shows each request to the app as it happens. [kamal-proxy](/reference/glossary#kamal-proxy), Kamal's web proxy on each server, logs every request. Meridian reads that log on every server the app runs on, and shows you only the app's own requests.

On an app's page, click **Traffic**.

## Before you start

- Each server runs the [agent](/reference/glossary#agent) with `MERIDIAN_LOGS=1`. Traffic uses the same setting as logs. See [Turn logs on](/guides/live-stats-and-logs#turn-logs-on). A server without it shows `Logs are off on web-1's agent. Set MERIDIAN_LOGS=1 there to turn them on.`
- The agent has reported kamal-proxy on at least one of the app's servers. Until then the page says `No kamal-proxy reported for shop`.

## What a request shows

Each request is one line:

```text
web-1  200 GET shop.example.com/cart?…  4.2 ms  → shop-web-3f2a9c1e5b7d  from 203.0.113.7
```

- The chip at the start: the server the request came through.
- The status, coloured: green below 300, muted for 3xx, amber for 4xx, red for 5xx.
- The method, host and path. A query string shows as `?…`, since it is often a long cache buster. Click the line to read it.
- How long kamal-proxy took to answer.
- The container that answered, by name and short version, when Meridian knows it.
- Who asked, after `from`: the client address. Behind Cloudflare, you see the visitor's address and country and the Cloudflare location, such as `from 198.51.100.4 SG via SIN`. That needs the headers in [Behind a Cloudflare Tunnel](#behind-a-cloudflare-tunnel).

Click a line to see every other field kamal-proxy logged. **Filter lines** searches those fields too.

The bar above the lines has **Filter lines**, **Wrap**, **Follow** and **Clear**, as on a logs page. It also has one chip per server, to hide or show that server's lines.

## Which servers and lines

Meridian reads kamal-proxy on up to 20 servers. These are the servers where the app has containers, and where Git places it.

kamal-proxy logs every app's requests in one stream. Meridian keeps only lines whose `service` is one of the app's:

| Line's `service` | For |
| --- | --- |
| `shop-web` | each role, as `<service>-<role>` |
| `shop-web-production` | an app with a destination, as `<service>-<role>-<destination>` |

Other apps' requests and kamal-proxy's own lines stop at Meridian and never reach the page.

<Note>
The page shows requests from the moment you open it, with no history. Meridian doesn't store traffic, so a request served while nobody had the page open doesn't show up later.
</Note>

## Behind a Cloudflare Tunnel

Through a tunnel, every request reaches kamal-proxy from `cloudflared`. So the client address is the tunnel connector's, not the visitor's. Log Cloudflare's headers to see the visitor:

```yaml config/deploy.yml
proxy:
  logging:
    request_headers:
      - Cf-Connecting-Ip
      - Cf-Ipcountry
      - Cf-Ray
```

Then each request shows the visitor's address and country, and the Cloudflare location from the end of `Cf-Ray`, such as `SIN`. **New app** adds this block when the project has a tunnel. For any other app, add it and deploy. See [Cloudflare Tunnel](/guides/cloudflare-tunnel#traffic-behind-a-tunnel).

## How long it streams

Traffic streams the same way as logs. While the page is open, it renews its request every 10 seconds. Close the page, and the agents stop within 30 seconds. The details are in [How the stream works](/guides/live-stats-and-logs#how-the-stream-works).

## Nothing is stored

Meridian passes request lines on to the open page and keeps them nowhere else. They go through the cable database, which keeps each message for about a minute.
