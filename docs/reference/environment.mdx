This page lists every environment variable Meridian reads, with its default. Meridian keeps everything specific to your site here, so it stays out of the database and out of Git.

Settings you change inside the app are on [Settings](/operate/settings). The **Connections** card on that page shows what Meridian read from the environment: GitHub, webhooks and the Kamal version.

In Meridian's own `config/deploy.yml`, put plain values under `env.clear` and secrets under `env.secret`. [Kamal](/reference/glossary#kamal) reads the secrets from `.kamal/secrets`:

```yaml config/deploy.yml
env:
  clear:
    MERIDIAN_URL: https://meridian.example.com
    SOLID_QUEUE_IN_PUMA: true
  secret:
    - SECRET_KEY_BASE
    - GITHUB_APP_ID
    - GITHUB_APP_PRIVATE_KEY
    - GITHUB_APP_WEBHOOK_SECRET
```

## Meridian

<ResponseField name="SECRET_KEY_BASE" type="string" required>
  The key that signs session cookies, and the grants that open live logs and traffic. Rails reads it in production. Make one with `openssl rand -hex 64`.

  Meridian also derives the first-run setup code from it, and `bin/rails meridian:setup_code` prints that code. If you change this key, everyone is signed out and the setup code changes.
</ResponseField>

<ResponseField name="MERIDIAN_URL" type="string" required>
  The address people and agents use, for example `https://meridian.example.com`. Meridian reads it in production only.

  - An `https://` URL turns on forced HTTPS, HSTS (a header that tells browsers to use HTTPS only) and secure cookies. It also trusts the proxy in front that handles TLS, which is [kamal-proxy](/reference/glossary#kamal-proxy).
  - A plain `http://` URL turns all of that off. Use it to try Meridian on a local network.
  - Meridian answers only requests for this URL's host, in the `Host` header. It refuses every other host, except `/up`, which kamal-proxy calls by IP address.
  - Unset, Meridian forces HTTPS and answers to any host.

  The agent reads a variable with the same name. See [Agent](#agent).
</ResponseField>

<ResponseField name="RAILS_LOG_LEVEL" type="string" default="info">
  How much Meridian logs in production: `debug`, `info`, `warn`, `error` or `fatal`. Meridian logs to standard output, which `kamal app logs` reads. `debug` can log personal data.
</ResponseField>

## GitHub

Meridian talks to GitHub as a GitHub App, or with a personal access token. When `GITHUB_APP_ID` and `GITHUB_APP_PRIVATE_KEY` are both set, Meridian uses the App, even if `GITHUB_TOKEN` is set too. See [GitHub App](/reference/github-app).

<ResponseField name="GITHUB_APP_ID" type="string">
  The GitHub App's ID, from the App's settings page. You need it to use the App.
</ResponseField>

<ResponseField name="GITHUB_APP_PRIVATE_KEY" type="string">
  The App's private key: the whole PEM file that GitHub gives you. Meridian turns each literal `\n` into a new line, so the key can sit on one line. You need it to use the App.
</ResponseField>

<ResponseField name="GITHUB_APP_WEBHOOK_SECRET" type="string">
  The secret Meridian uses to check the `X-Hub-Signature-256` header on `POST /webhooks/github`. That header proves a [webhook](/reference/glossary#webhook) came from GitHub.

  Unset, Meridian refuses every webhook with `401`. It then finds changes by polling GitHub every 30 seconds, and Settings shows **Webhooks: Off**. With a token, give your repository webhooks this same secret.
</ResponseField>

<ResponseField name="GITHUB_TOKEN" type="string">
  A personal access token to use in place of a GitHub App. Meridian makes every call as the token's owner. In this mode, projects need no installation ID. For the scopes it needs, see [Using a token instead](/reference/github-app#using-a-token-instead).
</ResponseField>

<ResponseField name="GITHUB_API_URL" type="string" default="https://api.github.com/">
  The address of the GitHub API. Set it for GitHub Enterprise Server, for example `https://github.example.com/api/v3/`. Links to repositories, commits and files go to the same host, without `/api/v3`.
</ResponseField>

### Credentials fallback

When a GitHub variable is unset or empty, Meridian reads it from Rails credentials instead:

| Variable | Credentials key |
| --- | --- |
| `GITHUB_APP_ID` | `github.app_id` |
| `GITHUB_APP_PRIVATE_KEY` | `github.private_key` |
| `GITHUB_APP_WEBHOOK_SECRET` | `github.webhook_secret` |
| `GITHUB_TOKEN` | `github.token` |

The published image has no `config/credentials.yml.enc`. So this matters only if you build your own image with one, and then Rails needs `RAILS_MASTER_KEY` to decrypt it. `GITHUB_API_URL` has no fallback.

## Server tuning

Meridian runs on Puma, the Rails web server, and runs background jobs with Solid Queue. These variables size them.

<ResponseField name="SOLID_QUEUE_IN_PUMA" type="boolean" default="true">
  Runs the Solid Queue supervisor inside Puma, so one container serves pages and runs jobs. Any value other than `false` keeps it on.

  To run jobs outside the web process, set it to `false` and run `bin/jobs` in a separate `job` role. See [Scaling](/operate/scaling).
</ResponseField>

<ResponseField name="JOB_CONCURRENCY" type="integer" default="1">
  The number of Solid Queue worker processes. Each one runs 3 threads over every queue.
</ResponseField>

<ResponseField name="RAILS_MAX_THREADS" type="integer" default="3">
  Puma's threads per process. It also sets the size of each SQLite connection pool, which defaults to 5 when this is unset. Keep the pool at least as large as the thread count.
</ResponseField>

<ResponseField name="WEB_CONCURRENCY" type="integer">
  Puma reads this itself to start more worker processes. Meridian's `config/puma.rb` sets no workers, so leave it unset and run one process.
</ResponseField>

<ResponseField name="PORT" type="integer" default="3000">
  The port Puma listens on. In the image, Thruster listens on port 80 and passes requests to Puma on 3000. So change it only if you also change Thruster.
</ResponseField>

<ResponseField name="PIDFILE" type="string">
  Where Puma writes its PID file. It is unset in production, so Puma writes none.
</ResponseField>

## Agent

The [agent](/reference/glossary#agent) reads these in `agent/config.go`. If a value is bad, the agent stops at start with exit code 2, and logs a line that names the variable. See [Install the agent](/guides/agent).

<ResponseField name="MERIDIAN_URL" type="string" required>
  Meridian's base URL, `http://` or `https://`, for example `https://meridian.example.com`. The agent drops a trailing `/`.

  The agent sends snapshots to `$MERIDIAN_URL/agent/snapshots` and opens the live line at `$MERIDIAN_URL/cable`. You don't need it with `-print`.
</ResponseField>

<ResponseField name="MERIDIAN_TOKEN" type="string" required>
  The agent token, which you create on the **Agents** page. The agent sends it as `Authorization: Bearer` on snapshots and on the live line. You don't need it with `-print`.
</ResponseField>

<ResponseField name="DOCKER_HOST" type="string" default="unix:///var/run/docker.sock">
  Where to reach the Docker API: `unix://…` or `tcp://host:port`. Point it at the read-only socket proxy, for example `tcp://<service>-meridian_docker:2375`.
</ResponseField>

<ResponseField name="MERIDIAN_INTERVAL" type="duration" default="15s">
  How often the agent sends a snapshot. Use a Go duration (`30s`, `1m`) or plain seconds (`30`), at least `1s`.

  The agent moves each wait by a random ±20%, so a fleet of agents doesn't report all at once. A server turns stale after three intervals, and never sooner than 45 seconds.
</ResponseField>

<ResponseField name="MERIDIAN_LABELS" type="string">
  Labels for the server, as `key=value` pairs separated by commas: `region=sgp,provider=ovh`. The board groups and filters by them.

  `lat` and `lng` (or `latitude`, `lon`, `longitude`) place the server on the map. Meridian keeps up to 32 labels.
</ResponseField>

<ResponseField name="MERIDIAN_MACHINE_ID" type="string">
  An ID for the host that never changes. Unset, the agent reads `/host/etc/machine-id`, then `/etc/machine-id`. The agent needs an ID from one of these, or it does not start.
</ResponseField>

<ResponseField name="MERIDIAN_HOSTNAME" type="string">
  The host name to report. Unset, the agent reads `/host/etc/hostname`, then falls back to the container's own host name. It must be a plain host name, because **New app** writes it into Kamal configs.
</ResponseField>

<ResponseField name="MERIDIAN_LIVE" type="boolean" default="true">
  Keeps the live line to `/cable` open, for live stats, logs and traffic. `0` or `false` turns it off: no WebSocket, no stats streams, no `/proc` reads and no logs.
</ResponseField>

<ResponseField name="MERIDIAN_LOGS" type="boolean" default="false">
  `1` or `true` lets Meridian follow the logs of Kamal containers while a deployer reads them. It needs the live line, so `MERIDIAN_LIVE=0` turns it off too. The accessory template sets it to `1`.
</ResponseField>

<ResponseField name="-print" type="flag">
  A command-line flag, not a variable. `meridian-agent -print` collects one snapshot, prints it as JSON to standard output, and exits. It needs no URL or token.
</ResponseField>

## CI

The [CI workflow](/reference/glossary#ci-workflow), `.github/workflows/meridian-deploy.yml`, reads one repository variable and two required repository secrets. See [CI workflow](/reference/ci-workflow).

<ResponseField name="MERIDIAN_RUNS_ON" type="repository variable" default="ubuntu-latest">
  The runner that both jobs use. Set it to `self-hosted`, or to one of your runner labels, when GitHub's hosted runners can't reach your servers. Set it in the infra repository under **Settings → Secrets and variables → Actions → Variables**.
</ResponseField>

<ResponseField name="KAMAL_SSH_PRIVATE_KEY" type="repository secret" required>
  The private key Kamal uses to connect to your servers over SSH. The workflow loads it into an `ssh-agent`.
</ResponseField>

<ResponseField name="KAMAL_REGISTRY_PASSWORD" type="repository secret" required>
  The password Kamal uses to log in to your image registry, as `registry.password` names it in your configs.
</ResponseField>

The workflow passes every other repository secret to the Kamal step as an environment variable with the same name. So `.kamal/secrets` can read it as `$NAME`.

<ResponseField name="CI" type="string">
  CI systems set this. When it is present, the Rails test environment loads the whole app before tests run. That catches load errors that lazy loading would hide.
</ResponseField>

## Tasks and development

<ResponseField name="BUNDLE_GEMFILE" type="string">
  When it is unset, `config/boot.rb` sets it to Meridian's `Gemfile`. The config parser always gets Meridian's `Gemfile`.
</ResponseField>

`bin/kamal-parse` reads your Kamal configs, and it runs with an empty environment. Meridian passes it only `BUNDLE_PATH`, `BUNDLE_WITHOUT`, `BUNDLE_DEPLOYMENT`, `BUNDLE_FROZEN`, `GEM_HOME` and `GEM_PATH`. It adds its own `BUNDLE_GEMFILE`, `PATH`, `HOME` and `LANG`. So ERB code in a Kamal config can't read any variable on this page. See [Security](/operate/security).

## Ignored

Meridian and the agent don't read these names. Remove them from your configs.

| Variable | Why |
| --- | --- |
| `MERIDIAN_PROXY_STATE` | The agent doesn't read kamal-proxy's state file. |
| `OIDC_*` | Meridian has no OpenID Connect sign-in. People sign in with email and password. |
