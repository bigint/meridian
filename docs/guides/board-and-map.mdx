The board tells you whether every server runs what Git says it should. Each cell is one app on one server, marked with its [drift](/reference/glossary#drift) state: how what runs differs from Git. The map shows the same cells by place. Both update as [agents](/reference/glossary#agent) report, without a reload.

## The board

The board is Meridian's home page, `/`. Its header counts the apps and servers it shows. It says `all matching Git` when every cell is in sync.

On a new install, **Getting started** lists three steps: **Connect your infra repository**, **Put the agent on your servers**, and **Deploy something**. It ticks each one off as it happens, and goes away once all three are done.

### Needs attention

**Needs attention** lists problems as sentences, most urgent first:

| Order | State | Sentence |
| --- | --- | --- |
| 1 | Missing | **shop** isn't running on **web-1**, but Git says it should. |
| 2 | Drifted | **shop** on **web-1** runs `v1.4.1`, not `v1.4.2` from Git. |
| 3 | Stray | **shop** is running on **web-3**, but Git doesn't put it there. |
| 4 | Stale | **web-2**'s agent has gone quiet. |

Each item says what it probably means, and has a button: **Open shop**, **Open server**, or **See agents**. The first four items show. The rest sit under a link such as `3 more things need attention`. The **Board** link in the sidebar shows the same count.

<Accordion title="How items are grouped">
  When only part of an app's roles are missing or stray, the sentence names those roles. A quiet agent is one item for its server, not one per app on it. More than three quiet servers become one item, such as **5 agents** have gone quiet.
</Accordion>

### The grid

**Every app on every server** is the grid. Pick how it reads:

- **Apps × servers**: one row per app. The **Git** column shows the newest release's version. Server columns sit under a heading for their group, such as a region.
- **Servers × apps**: one row per server, grouped into sections, with one column per app.

Each cell shows what the server reports:

| Cell | Means |
| --- | --- |
| `v1.4.2` | The running version, in the colour of its state: in sync, stray or stale. |
| `≠v1.4.1` | Drifted: a version other than Git's. |
| `✕` | Missing: Git puts the app here, and nothing runs. |
| `–` | Unknown: nothing to compare yet. |

A dashed cell means the agent is quiet or Meridian can't tell. Hover a cell to see the app, the server, the state and every version running. **What do these mean?** under the grid explains each state:

See [Drift](/concepts/drift) for how Meridian decides.

Click an app's name to open its page, where you deploy, redeploy and roll back. Click a server's name to open its page. See [Deploy](/guides/deploy).

### Filter by state

The chips above the grid count cells per state: **All**, then each state that has any. Click one to show only cells in that state. Click it again to clear it. The counts ignore the state filter, so you can move from one state to another.

### Filters

Open **Filters** for the rest, then click **Apply**. **Clear** removes every filter.

| Filter | Shows |
| --- | --- |
| **App** | Apps whose service contains the text. |
| **Project** | One project's apps. |
| **Region**, **Provider**, **Role** | Servers whose `region`, `provider` or `role` label has the value. The menus list the values in use. |
| **Group by** | **Automatic**, **Nothing**, **Region**, **Provider** or **Role**. |

Labels come from the agent's `MERIDIAN_LABELS`. See [Labels](/guides/agent#labels-and-map-location).

<Accordion title="How automatic grouping works">
  **Automatic** groups by region when the board shows more than 30 servers, or servers in more than one region. Otherwise it doesn't group. Under a region heading, a server's name drops the region part, so `aps2-az1-node-01` reads `az1-01`. Hover it for the full name. A server without the label goes under a heading such as **No region**.
</Accordion>

### Pages

The grid shows 25 rows a page, apps or servers depending on the view. **Previous** and **Next** sit under it, with `Page 1 of 3`. Every server or app that the page's rows use gets a column.

### URL parameters

Every filter lives in the URL, so a link opens the board as you left it.

| Parameter | Values | Example |
| --- | --- | --- |
| `view` | `apps` (default) or `servers` | `/?view=servers` |
| `state` | `in_sync`, `drifted`, `missing`, `stray`, `stale` or `unknown` | `/?state=drifted` |
| `app` | text the service contains | `/?app=shop` |
| `project` | a project's ID | `/?project=2` |
| `region`, `provider`, `role` | a label value | `/?region=sgp&role=web` |
| `group` | `region`, `provider`, `role` or `none`. Leave it out for automatic. | `/?group=provider` |
| `page` | a page number | `/?page=2` |

## Search

The box at the top of every page searches apps, servers and projects as you type. It matches:

- an app's service or destination,
- a server's name or hostname,
- a project's name or repository.

It shows the best eight. Names that start with what you typed come first, then shorter names. Press **Enter** to open the first result, or **Escape** to clear the box.

## The map

**Map** puts every server with a location on a world map. Servers within 60 km of each other are one place, about one metro area. Each place is a dot that grows with its number of servers.

<Frame>
  <img className="block dark:hidden" src="/screenshots/map.png" alt="The map: places as dots, with lines between places that share apps" />
  <img className="hidden dark:block" src="/screenshots/map-dark.png" alt="The map: places as dots, with lines between places that share apps" />
</Frame>

A place takes the worst state of its cells. On the map you also see:

- **Lines** between places that run the same app. A line is thicker when the places share more apps. Stray cells don't count.
- **Flows** for Meridian's own traffic: agents reporting in, and deploys going out to places being deployed. They need a location for Meridian itself. Set it in **Settings**, under **Where Meridian runs**.
- **Names** for Meridian, and for places that need attention or are being deployed. Hover any other dot to see its name.

<Accordion title="How a place gets its name and state">
  A place is named after its servers' most common `city` label. Without one, it uses their most common `region` label, else its first server's name. Its state is the worst of its cells, in the order missing, drifted, stray, stale, unknown, in sync. A place with no cells is in sync if any of its servers reports, and unknown if none does.
</Accordion>

### Chips

The chips above the map count apps, places and deploys:

- **App** chips, when there are between two and eight apps. Click one to show only that app's cells. Click it again to show every app.
- **Places** chips count places per problem state. **Deploying** counts places with a deploy under way.
- `Every place matches Git` shows when no place has a problem and nothing is deploying.

**Filters** has **App**, **Project**, **Region**, **Provider** and **Role**, as on the board.

### Open a place and the Places table

Click a dot, or a name in **Places**, to open the place. A place with one server opens that server's page. A place with more opens the board filtered to its `region` label, or the whole board when its servers have none.

The **Places** table lists every place, problems first, with its region, its cells, and whether its agents report. Servers without a location are counted under the table.

### Give a server a location

Use either:

- **Agent labels.** Add `lat` and `lng`, in decimal degrees, to `MERIDIAN_LABELS`, such as `MERIDIAN_LABELS=region=sgp,city=Singapore,lat=1.35,lng=103.82`.
- **The server page.** Set **Latitude** and **Longitude** under **Location on the map** and click **Save location**.

If the agent reports `lat` and `lng`, its next report replaces the location set on the server page. See [Labels and map location](/guides/agent#labels-and-map-location).

## Live updates

When an agent's report changes something, Meridian refreshes the board, the map, and the app and server pages that show it. The page keeps its scroll position.

<Accordion title="How this works under the hood">
  Each part of a page refreshes at most once a second, however many reports arrive. Once a minute Meridian also redraws every part with a quiet agent, so its cells turn stale without a new report.
</Accordion>
