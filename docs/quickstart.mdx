Run Meridian on your own machine and point it at your real [infra repository](/reference/glossary#infra-repository), the Git repository that holds your Kamal configs. Meridian reads it and shows every app on the board. Nothing changes on your servers unless you press **Deploy**.

## Before you start

- [Docker](https://docs.docker.com/get-docker/) and `openssl`.
- An infra repository on GitHub with at least one Kamal config, such as `config/deploy.yml`.
- A GitHub personal access token that can reach that repository. A classic token needs the `repo` and `workflow` scopes. For a fine-grained token, see [Using a token instead](/reference/github-app#using-a-token-instead).

<Steps>
  <Step title="Start Meridian">
    ```bash
    docker run -d --name meridian -p 127.0.0.1:3000:80 \
      -v meridian:/rails/storage \
      -e SECRET_KEY_BASE=$(openssl rand -hex 64) \
      -e MERIDIAN_URL=http://localhost:3000 \
      -e GITHUB_TOKEN=github_pat_… \
      ghcr.io/bigint/meridian:v0.1.5
    ```

    `127.0.0.1:` keeps Meridian on your own machine: without it, Docker publishes the port to your whole network, over plain HTTP. The `meridian` volume holds Meridian's SQLite databases. `MERIDIAN_URL` is the address you open Meridian at. A plain `http://` address turns off the redirect to HTTPS, which you want on your own machine. `GITHUB_TOKEN` is your token: Meridian makes every GitHub call as its owner.
  </Step>

  <Step title="Create your account">
    Open [localhost:3000](http://localhost:3000). Meridian shows **Welcome to Meridian** and asks for a **Setup code**. Opening the page writes the code to the container's log. Read it:

    ```bash
    docker logs meridian 2>&1 | grep "setup code"
    ```

    ```text Output
    [5f1c2e3a-8d4b-4f6e-9a7c-2b1d0e3f4a5b] Meridian setup code: 3e1f0c9a8b7d6e5f4a3b
    ```

    Paste the code in. Add your name, an email and a password of at least 12 characters, and press **Create account**. Meridian signs you in and opens **Projects**.

    <Tip>
    `docker exec meridian bin/rails meridian:setup_code` prints the same code.
    </Tip>
  </Step>

  <Step title="Add your infra repository">
    On **Projects**, press **Add project**. Fill in:

    - **Repository:** `owner/name`, such as `acme/infra`.
    - **Branch:** the branch your configs live on, such as `main`.
    - **Config paths:** where your Kamal configs are. The default, `config/deploy*.yml`, finds `config/deploy.yml` and its destination files. Leave **GitHub App installation ID** empty: a token needs none.

    Press **Create Project**. Meridian reads the repository and lists every config it found. A config Kamal can't parse shows its file and line.
  </Step>

  <Step title="Look at the board">
    Open **Board** in the sidebar. Each row is an [app](/reference/glossary#app), one config plus one destination, and each column is a server from your configs.

    Every cell is **Unknown** for now. Git says what should run, but no [agent](/reference/glossary#agent) is reporting what does run. Install the agent on your servers to fill the cells in. See [Install the agent](/guides/agent).

    The [tour](/tour) covers every screen.
  </Step>
</Steps>

## Clean up

This removes the container and its data:

```bash
docker rm -f meridian
docker volume rm meridian
```
