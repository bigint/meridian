This page shows each screen in Meridian, in the order of the sidebar. Each section says what the screen shows, what you can do there, and which page covers it in full.

The sidebar has the screens you watch at the top. Under **Manage** are the screens that set Meridian up. **Settings** and **Jobs** are at the bottom.

The board, the map, and the app and server pages update themselves. When an agent reports a change or a deploy moves on, they redraw in place and keep your scroll position.

## Board

The board, at `/`, answers one question: does every server run what Git says? The header counts the apps and servers. It says **all matching Git** when every cell is in sync.

<Screenshot name="board" alt="The board: Getting started, Needs attention, and the grid of every app on every server" />

**New app** is at the top right. On a new install, **Getting started** lists three steps and ticks each one off:

1. Connect your infra repository.
2. Put the agent on your servers.
3. Deploy something.

The list goes away when all three are done.

### Needs attention

**Needs attention** lists what to look at, worst first, as plain sentences:

| State | Sentence | Button |
| --- | --- | --- |
| Missing | **shop** isn't running on **web-1**, but Git says it should. | **Open shop** |
| Drifted | **shop** on **web-1** runs `v41`, not `v42` from Git. | **Open shop** |
| Stray | **shop** is running on **web-9**, but Git doesn't put it there. | **Open shop** |
| Stale | **web-1**'s agent has gone quiet. | **Open server** |

A second line gives the likely cause, such as **A deploy may still be rolling out, or it stopped part-way.** The board shows four items. The rest are under a disclosure such as **3 more things need attention**. The number next to **Board** in the sidebar counts the whole list.

### Every app on every server

The grid shows each app against each server it runs on, or should run on. Each cell shows the version that runs there, marked by its [drift](/reference/glossary#drift) state. Drift is the difference between what Git says should run and what the server's agent sees. The **Git** column shows each app's newest release. Hover over a cell to see the app, the server, the state and the version.

Above the grid:

- **The state chips** count the cells in each state. Press **Drifted** to show only drifted cells. Press it again, or **All**, to show every cell.
- **Apps × servers** and **Servers × apps** turn the grid around.
- **Filters** narrow the grid by **App**, **Project**, **Region**, **Provider** and **Role**, and set **Group by**.
- **What do these mean?** explains each state.

The grid shows 25 rows a page. The filters and the page are in the URL, such as `/?state=drifted&region=sgp`. So you can share a view as a link. See [board and map](/guides/board-and-map).

Click an app's name to open its page, where you deploy, redeploy and roll back. Click a server's name to open its page. See [deploy and roll back](/guides/deploy).

## Search

The search box at the top of every page finds apps, servers and projects as you type. It matches an app's service or destination, a server's name or hostname, and a project's name or repository.

<Screenshot name="search" alt="Search results for a partial name: apps, servers and projects, best match first" />

It shows the eight best matches. Names that start with what you typed come first, then shorter names. Press <kbd>Enter</kbd> to open the first match, or <kbd>Esc</kbd> to clear the box.

## Map

The map, at `/map`, puts every server that has a location on a world map. Servers within 60 km of each other share one dot, called a place. Each dot takes the colour of the worst state there. A line joins two places that run the same app, and gets thicker the more apps they share.

<Screenshot name="map" alt="The world map: places as coloured dots, and lines between places that share apps" />

Click a place to open it: its server's page when it has one server, or else the board filtered to its region. **Places** lists every place, worst first, with what runs there. The **App** chips show one app's cells. **Filters** narrows the map by **App**, **Project**, **Region**, **Provider** and **Role**, as on the board.

A server needs a location to appear. Its agent can send `lat` and `lng` labels, or you can set one on the server's page. The map lists the servers that have none. See [board and map](/guides/board-and-map).

## Apps

**Apps**, at `/apps`, lists every [app](/reference/glossary#app): one row for each Kamal config and [destination](/reference/glossary#destination). Each row shows the app, its project, its kind, its hostnames, its config file and its latest release. **Search apps** filters the list.

### New app

Press **New app** on the board to add an app. Meridian writes a Kamal config from a form, checks it with Kamal, and opens a pull request on the infra repository. The form asks for:

| Field | What it sets |
| --- | --- |
| **Infra repository** | The project the config goes to. |
| **Name** | The Kamal service. |
| **Source repository** | Where the app's code and Dockerfile live, as `owner/name`. |
| **Kind** | **Static** (nginx, port 80), **Node** (Next.js, port 3000), **Rails** (port 80) or **Other** (port 3000). |
| **Hostname** | The domain that kamal-proxy serves the app on. |
| **Servers** | The servers to run on, or **every server with these labels**, such as `role=web,region=sgp`. |
| **Destination** | Optional. Writes a base config plus a destination file. |
| **Port**, **Registry**, **First version** | The app port, the registry host, and the image tag to deploy once the pull request is merged. |

Press **Open pull request**. The next page lists the files, what is **Still to do by hand**, and Dockerfile advice for the kind. The app shows on the board once you merge the pull request. See [add a new app](/guides/new-app).

## App page

The app's page, at `/apps/<id>`, has everything about one app. The header shows its kind, its project, its hostnames as links, and how many servers run its newest release.

<Screenshot name="app" alt="An app's page: servers with their versions and health, releases with Roll back, and Ship a version on the right" />

| Section | What it shows |
| --- | --- |
| **Traffic** and **Logs** | The app's live requests and container logs. See [traffic](/guides/traffic) and [live stats and logs](/guides/live-stats-and-logs). |
| **Servers** | Each server, with the version it runs, its state, roles, health and place. |
| **Accessories** | The config's accessories, such as a database, with their image, server, state and start time. |
| **Releases** | The last 20 releases from the version file's Git history. The newest has **Roll back**. |
| **Configuration** | The config file, image, roles, version file, source repository and secret names. |
| **Ship a version** | A version box and **Deploy**, with past releases as suggestions. **Redeploy** runs the deploy workflow again for the current version. |
| **Current deploy** | The last deploy's CI status, who started it, its commit and a link to the CI run. Each server shows its progress as its agent reports the new version. |

## Servers

**Servers**, at `/servers`, lists every machine that Git names or an agent reports from. Each row shows the server, its hostname, place, labels, agent version and when it was last seen. A quiet server is marked **Silent**, and one no agent has reported from says **No agent yet**. **Search servers** filters by name or hostname. **Only silent agents** shows only quiet servers.

## Server page

A server's page, at `/servers/<id>`, shows one machine. The header says **Reporting**, **No agent yet**, or **… Silent**.

<Screenshot name="server" alt="A server's page: live host tiles, the apps on it, and every container with live CPU, memory and network" />

| Section | What it shows |
| --- | --- |
| **Host** | Live CPU, memory, load and disk while the page is open. These need the agent's `/proc` mount. |
| **Apps** | Each app here, with the version it runs, its state and its roles. |
| **Containers** | Each container that Kamal started, with its version, state, health, live CPU, memory and network, and start time. Each row has a **Logs** button. |
| **Machine** | The hostname, agent version, last seen time, location and projects. |
| **Labels** | What the agent sent in `MERIDIAN_LABELS`, except `city`, `region`, `lat` and `lng`. |
| **Location on the map** | Set a **Latitude** and **Longitude**, then press **Save location**. |

See [servers and agents](/concepts/servers-and-agents).

## Activity

**Activity**, at `/events`, is the audit log. It lists each change Meridian made, with who did it. Entries are grouped by day, newest first, 50 to a page.

<Screenshot name="activity" alt="The activity log: deploys, rollbacks and project changes grouped by day, each with who did it and its commit" />

Each entry shows a sentence, such as **Deployed shop · production to v42**. It also shows who did it, the action name such as `app.deploy`, and the commit. A link to the pull request shows where there is one.

Under **Filters**, **Action starts with** takes a start such as `app.` or `project.`. See [activity events](/reference/activity-events) for every action name.

## Projects

**Projects**, at `/projects`, lists your infra repositories. Each one shows its app count, its last sync and its problems. Add one with **Add project**.

A project's page has these parts:

- **Sync now** reads Git at once, instead of within 30 seconds.
- **Add CI workflow** opens a pull request with `.github/workflows/meridian-deploy.yml`.
- **Edit** changes the repository, branch, installation ID and config paths. **Remove project** is at the top of the edit page.
- **Repository** shows the branch, the config paths and the last sync. It also says whether changes arrive as pull requests or direct commits.
- **Parse errors** lists each error with its file and line.
- **Configs found** lists every app with its config, destination, server count and hostnames.

Removing a project removes it from Meridian only. Nothing in Git changes. See [projects](/guides/projects).

## Agents

**Agents**, at `/agents`, is where you connect servers. **Install** shows the two Kamal accessories to add, with your Meridian URL filled in. **Connect a server** lists the steps.

Create a token with **Create token**. Give it a **Label**. Tick **Fleet token, shared by many servers** for one token that many servers share. Meridian shows the token once. **Tokens** lists each token with its server and when it was last used, and **Revoke** cuts one off.

**Silent agents** lists each server whose agent has gone quiet. Then it lists the servers that no agent has ever reported from. See [install the agent](/guides/agent).

## Tunnels

**Tunnels**, at `/tunnels`, shows each Cloudflare Tunnel that your configs run. Each one shows its token secret and whether Meridian set it, how many connectors run, the apps it serves, and what needs fixing.

**Set up a tunnel** lists the steps in order: in Cloudflare, in Git, on the servers, then the routes in Cloudflare. Press **Edit connectors** to choose the servers that run a connector. Meridian proposes that as a change to the config. Meridian never calls Cloudflare's API. See [Cloudflare Tunnel](/guides/cloudflare-tunnel).

## Secrets

**Secrets**, at `/secrets`, lists the secret names that each project's configs use, from `env.secret` and `registry.password`. Each row shows the apps that use the name, and when someone last set it from Meridian.

Type a value under **Set or rotate**. Meridian encrypts it into the repository's GitHub Actions secrets and keeps nothing. **Add another name** adds a name that no config uses yet, with an optional value. See [secrets](/guides/secrets).

## Settings

**Settings**, at `/settings`, has two cards saved together with **Save**:

- **Where Meridian runs** sets a **Place**, **Latitude** and **Longitude**. The map draws Meridian there, with agent reports flowing in and deploys flowing out.

Beside them, **Connections** shows how Meridian reaches GitHub and the Kamal version it reads configs with. These come from Meridian's environment, so you can't change them here.

**Your account** changes your **Name**, **Email** and password. Press **Save account** to keep the changes. See [settings](/operate/settings).

**Jobs**, in the sidebar, opens the background jobs dashboard at `/jobs`.

## The account menu

Your name at the top right opens the account menu. It shows your name and email, a **Theme** switch between **System**, **Light** and **Dark**, and **Sign out**. The browser saves the theme, not your account. The sidebar's **Collapse sidebar** button shrinks the sidebar to a row of icons.
